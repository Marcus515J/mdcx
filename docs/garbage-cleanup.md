# 统一文件清理

入口只有「设置 → 刮削目录 → 文件清理设置」，原有“垃圾处理设置…”弹窗已合并到此页。

- “扩展名等于”、“文件名等于”、“文件名包含”及排除规则共用一套。
- 完整文件名必须含扩展名，空格和大小写严格一致；多个文件名用 `|` 分隔，近似名称不会命中完整文件名规则。
- 包含词去除空白并忽略大小写；广告关键词也在原有“文件名包含”中编辑，不再维护另一份黑名单。
- 排除规则在启用时优先。正常番号视频、NFO、图片、字幕和符号链接受保护。
- 非视频文件必须命中扩展名、完整文件名或包含词；不会仅因 0 KB 或很小就删除普通笔记或未知文档。
- 无番号视频还可命中域名样式、严格小于 N MB，以及已有正数 KB 门槛；KB 门槛为 0 时不启用大小清理。

在同一页选择演练/真实处理、移到待删/永久删除、待删目录、域名开关和 N。
点击页面底部“保存”写入当前 JSON。“刮削时自动清理”控制自动扫描；关闭它仍可点击原有“点击检查待刮削目录并清理文件”手动清理，无需联网或成功刮削。
手动按钮先保存当前页面；演练不会移动、删除文件或清理空目录。两个旧版仅用于永久删除的确认框已由明确的处理方式选择取代。

| JSON 键 | 默认值 | 说明 |
|---|---|---|
| `garbage_enabled` | `false` | 刮削时自动清理；与已有 `clean_enable` 中 `auto_clean` 同步 |
| `clean_contains`（已有） | 原有 8 项加 `台湾uu`、`美少女直播`、`信誉保证`、`最新情報` | 唯一包含词列表；`最新情报` 原已存在 |
| `clean_name`（已有） | `["uur76.mp4", "uur93.com.mp4"]` | 完整文件名严格匹配 |
| `garbage_domain_rule` | `true` | 无番号视频去空白后检查 `.com`、`.net`、`.cc`、`www.` |
| `file_size`（已有） | `100.0` | N，MB（1024² 字节），仍与原有最小视频大小共用一个值 |
| `garbage_permanent_delete` | `false` | 关闭时移动，开启时永久删除匹配的单文件 |
| `garbage_directory` | `""` | 留空为源文件盘符/卷根下 `_待删`；可设绝对路径 |
| `garbage_dry_run` | `false` | 演练：记录日志，匹配视频跳过搜索 |

不新增配置项或依赖。旧测试版 `garbage_keywords` 自动合并到 `clean_contains` 并去重，保存新版时不再输出这份重复列表；旧关键词、完整文件名、排除项和启用状态保留。
旧 JSON 缺少新字段时使用默认值；旧自动清理开关映射到同一页。加载原 JSON 不会覆盖原文件，只有保存时才写入新版格式。
其余现有的目录、网络、Cookie、站点、模型、命名、字段优先级等沿用现有加载/保存机制。尚未收到用户实际旧 JSON，具体文件的对照迁移需收到后再验证。

## 目录与文件安全

纯垃圾子目录在整轮结束后整体移到待删，保持结构；媒体根目录不移动。手动清理也执行相同的目录判断。
未知文件、正常视频、NFO、图片、字幕、排除项及链接会阻止整体移动，但同目录里明确匹配的其他垃圾文件仍可单独处理。
即使选择永久删除单文件，纯垃圾目录仍按已明确的补充要求整体移到待删。

`_待删` 及自定义待删目录（包括子目录）始终排除，手动、自动和显式刮削任务均不会扫描它。
同名文件/目录加 `_1` 等序号，已有目标不会覆盖。移动/删除有命中原因、源路径、方式及目标日志；失败保留源文件。
目录先复制到独占创建的目标，再核对文件未变化，只移除已复制的垃圾文件及空目录。复制失败或源目录变化时保留源目录；可能留下待删副本。
