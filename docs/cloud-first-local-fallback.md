# 云端优先，本机 Hy-MT2 兜底

2026-10-11：根据用户最新决定，第二阶段顺序调整为：
**云端 API → 同模型重试一次 → 本机 Hy-MT2 → 对应字段原文**。

当前 `test-20261011-local-hymt2-reviewfix` EXE 已支持这一顺序，只需调整配置；
不改翻译业务代码，不重做第一阶段，不需要重新下载程序或模型。

服务日志有六次推理启动记录，时间与 MDCx 三条影片的标题/简介翻译吻合。

本机加载和实际推理已经验证。后续两轮日志进一步确认主接口报错/拒绝后转本机的路径走通，
但第一轮也有五个字段转本机，云端正常使用与译文准确性仍需核查。

## 在现有测试版配置

打开「设置 → 翻译 → LLM 翻译」。

| 控件 | 填写内容 |
| --- | --- |
| API URL | 原来可用的云端 OpenAI 兼容地址 |
| Model | 原来可用的云端模型名 |
| API Key | 自己的云端 Key，只在本机填写 |
| 云端主模型尝试 | **1** |
| 拒绝 / 不可用重试 | **1** |
| 主模型超时（秒） | 可先用 **30**；正常云端请求超过此时间时按实际耗时调整 |
| 备用 API URL | **http://127.0.0.1:8080/v1** |
| 备用 Model | **HY-MT2-7B-Q8_0** |
| 备用 API Key | **留空** |
| 备用超时（秒） | **60** |

如果云端配置现在位于备用栏，先将其地址、模型、Key 复制到主接口栏，再填写本机备用。
如果主接口已被本机预设覆盖、备用栏又没有云端配置，从自己保存的原云端配置恢复这三个值。
程序没有保存一份隐藏的旧云端配置，不能自动找回被覆盖的值；无需上传私有 JSON 或 Key。

翻译服务**只勾选 LLM**，取消其他翻译引擎；当前版本多引擎会随机排列，
同时勾选 Google 等服务不能保证云端 LLM 最先调用。标题/简介的语言和翻译开关保持现有设置。
最后点击页面底部「保存」。

双击原有 `Start-HyMT2.cmd`，沿用已验证的程序和模型，等「服务已就绪」并保持窗口打开。
**旧启动窗口提示“点击本机预设”是此前本机优先的用法；新方案不要点击该按钮，
它会再次把主接口改为本机。** 此时启动器只负责让本机备用服务可用。
复用已有服务时，若启动器显示不同的实际模型名，将该名称填到「备用 Model」。

云端正常返回有效译文时，只使用云端；拒绝、请求错误、超时、空返回时同模型重试一次，
仍失败则请求本机一次。本机仍失败或拒绝就保留对应字段原文。
标题和简介各自走这条链，不覆盖另一字段已成功的译文。

## 下一步真实验收

1. 本机服务保持就绪，用一条媒体副本测试新的配置。预期云端完成翻译，
   详细日志没有「换备用模型」，本机日志没有这次新增推理。
2. 保存正确的云端模型名，临时将主 Model 改为一个不存在的名称
   `mdcx-fallback-test-invalid-model` 并保存，用另一条媒体副本测试。
   若云端返回模型错误，详细日志应按顺序出现「翻译不可用」「重试第 1 次」「换备用模型」，
   最终获得本机译文，服务日志出现新增推理。测试后恢复正确云端模型名并保存。
   有些兼容服务会忽略模型名或自动选择默认模型；这类服务如果正常返回译文，
   说明故障没有被触发，不能据此判定回退失败。
3. 本机也不可用时最终保留原文的路径已做模拟验证；如继续人工验证，
   使用独立媒体副本，并在测试后恢复云端配置和本机服务。

提供 MDCx 主日志、左下角请求信息面板的详细日志，以及服务窗口按回车正常停止后的
`server-stderr.log` 即可核对切换；`server-stdout.log` 为 0 KB 时不需要提供。
LLM 的主/备用调用都汇总为 `Llm`，仅看「翻译完成(Llm)」不能区分后端。
