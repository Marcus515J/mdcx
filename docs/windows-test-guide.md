# MDCx 第三阶段 Windows 测试版：软件内 Hy-MT2 管理

本版接续已验收的垃圾清理、翻译调用和故障回退，只集成模型管理并统一新增控件。主分支和旧测试版保留。

日常方案仍为 **DeepSeek 云端 → 同模型重试一次 → 本机 Hy-MT2 备用 → 对应字段原文**。
已有主 URL、Model、Key、私有标题/简介 Prompt 和温度保持原配置。无需上传私人 JSON，也无需重新执行已通过的人工故障测试。

## 软件内启动

1. 下载本发布的 EXE，沿用你的原配置。在「设置 → 翻译 → LLM 翻译」底部找到「本机 Hy-MT2 模型管理」。
2. 首次在查找位置输入大概安装在哪个盘，例如 `H`，点击「查找 / 验证路径」。也可输入多个盘符 `D E H`，或选择目录。多份程序/模型从列表选择；找不到时可用「浏览…」。扫描可取消。
3. 点击「启动备用模型」，等待状态显示已就绪。首次加载最长等待 180 秒；进度显示已等待时间。程序使用现有 llama-server 和 GGUF，不下载、不安装。
4. 启动成功只填写备用 URL/Model/Key，再点击页面底部「保存」。这同时记忆所选路径。下次可直接启动；「查找 / 验证路径」优先验证记忆路径，有效时不扫描；「重新查找」强制扫描。
5. 「停止」只停止本软件启动的服务。已就绪的外部服务可复用，但不能在这里停止。刮削期间停止按钮禁用，请结束刮削后再停止。退出 MDCx 会清理本软件启动的服务；取消退出、托盘隐藏和最小化不会停服。

备用地址固定为 `http://127.0.0.1:8080/v1`；新启动的模型 ID 为 `HY-MT2-7B-Q8_0`。复用外部服务时读取其实际 ID。
如果外部服务已被自动检测为就绪，可点击「将本机 Hy-MT2 设为备用」，再保存。这个按钮也只填写备用接口，不启动服务。

已验证的用户安装是 `H:\0AI\llama.cpp\llama-server.exe` 和 `H:\0AI\models\HY-MT2-7B-Q8_0.gguf`；本版通过查找或浏览选择，不将私人机器路径写成软件默认值。

## 本阶段桌面验收

- 软件内查找、选择、启动、保存路径、停止闭环；重开后无需再次全盘查找。
- 深浅主题，以及常用 100% / 150% / 200% 缩放：清理、翻译、模型管理标签和输入框可读，滚动后模型按钮、后续分组及底部保存可达。
- 缺失路径、端口占用、加载失败显示可读状态；「打开日志」可打开本轮服务日志。未知进程不会被强制关闭。
- 保存和重开后原云端配置、私有 Prompt、0.90 温度与其他设置保持。

本轮自动测试使用合成配置、临时服务程序和 HTTP 服务，不使用私人配置或真实模型。离屏主题/缩放检查不替代真实 Windows 桌面外观验收。

日志首先放在配置目录的 `logs/hymt2`；无法写入时使用本机应用数据目录。每轮有 manager、stdout、stderr 日志，不记录云端 Key 或 Prompt。
外部 ZIP 启动器继续作为可选入口；使用软件内启动时无需打开 ZIP。

清理规则和翻译回退沿用已验收实现，详见 [清理说明](garbage-cleanup.md)、[云端优先说明](cloud-first-local-fallback.md) 和 [阶段交接](stage3-handoff.md)。历史 NFO、模型语义评审、站点/bypass 网络问题不在本轮范围。
