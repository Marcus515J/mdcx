# MDCx Windows 第二阶段测试版：本机 Hy-MT2 与备用回退

这是独立预发布测试版，接续已验收的垃圾清理版本，只收尾清理页外观并完善本机翻译与备用设置。正式版和主分支未替换。

## 第二阶段先测这些

1. 从 Assets 下载 EXE 和 `start-local-hymt2.ps1`。运行脚本，选择海南鸡已有的 llama-server.exe 和 Hy-MT2 GGUF，等待加载完成并保持窗口打开。
2. 「设置 → 翻译 → LLM 翻译」点击“使用本机 Hy-MT2（海南鸡接口）”，确认本机地址、模型名，填写自己的备用 API 配置，点击底部“保存”。已有提示词和其他设置沿用；Key 不必上传。
3. 用少量媒体副本测试标题与简介；核对正常译文、同模型重试、备用和原文日志。每个字段默认最多两次本机请求、一次备用请求。
4. 停止本机服务后再测，日志应显示主模型请求失败、重试，再转备用；清空备用地址保存后应保留对应字段原文。
5. 检查清理页只有底部总保存、新旧输入框列对齐；在自己常用的主题和 100%/150%/200% 显示缩放下检查可读性及滚动。

实际本机模型、真实备用 API、用户私有配置、真实旧 NFO 未在云端验证。PowerShell 启动脚本不安装或下载依赖；详见 [本机接入说明](llm-refusal.md)。
第一阶段文件处理已经验收，下面保留其使用说明供参考，无需重新验收。

## 下载运行

在本 Release 下方的 **Assets** 下载名字以 `.exe` 结尾的文件；`Source code` 是源码，不是程序。
把程序放到独立测试目录后运行。已有配置仍可使用；测试时请选择新建的媒体测试目录，不要直接选整块盘。

## 统一文件清理设置

在「设置 → 刮削目录 → 文件清理设置」中直接编辑。原“垃圾处理设置…”弹窗已移除。

- 广告关键词统一填在“文件名包含”；多个项目用 `|` 分隔，匹配时忽略空白和大小写。
- 你明确指定的文件填在“文件名等于”，必须写完整名称含扩展名，空格和大小写严格一致。
- 扩展名、关键词和完整名称的“启用”开关控制对应规则；“不清理文件规则”优先。
- 选择演练模式、处理方式和待删目录，点击页面底部“保存”。
- 默认处理方式是移到待删；选择永久删除只作用于匹配的单文件，纯垃圾目录仍整体移到待删。
- “刮削时自动清理”只控制自动运行。关闭它仍能点击原有“点击检查待刮削目录并清理文件”手动清理，不需要网络或成功刮削。
- 正常番号视频、NFO、图片、字幕和链接受保护；非视频文档不会仅因很小或 0 KB 被清理。

待删目录留空表示源文件盘符根下 `_待删`，每轮显示演练/真实状态。测试期间关闭原有空目录删除及刮削后自动退出，方便核对。

## 如何测试你截图中的文件

在新的测试媒体目录中，使用文件副本准备一个子目录：

1. 一个带空格的广告 HTML，例如 `聚 合 全 網 H 直 播.html`；启用 `.html` 扩展名规则即可命中。
2. 广告 TXT，例如 `最 新 位 址 獲 取：489155.com 收藏不迷路.txt`；包含词 `最新位址` 即可命中。
3. 一个自己确认的 `明确指定的广告.txt`；把完整名字加进“文件名等于”，并开启该规则。
4. 对照文件 `明确指定的广告.txt.bak`、0 KB `私人笔记.txt`，不把它们加入其他清理规则。

第一轮勾选演练，点击手动清理，日志应显示前三项命中，全部文件留在原位。
第二轮取消演练并保存，再点击手动清理，前三项按所选方式处理，后两项仍在原位，近似名称不会因完整名字规则被清理。

另建纯垃圾子目录，放垃圾视频及 `.url`，真实处理后应整目录出现在待删目录中。含正常视频、NFO、图片、字幕、未知文件的目录会保留，但其中明确命中的垃圾仍能单独处理。
待删目录里的同名文件应被保留，新文件加序号；再次运行不会扫描待删目录。
垃圾清理日志与正常刮削成功/失败统计独立，后者为 0 成功不代表垃圾清理失败。

## 旧 JSON 搬迁

可直接使用原 JSON，不必逐项重新配置。读取不会覆盖原文件，缺少新字段采用默认值；保存才写入新版格式。
上一测试版的垃圾黑名单会自动合并到原“文件名包含”中，完整文件名和排除规则保留，网络/站点/Cookie/模型等现有字段沿用原配置。
迁移后检查同页的自动清理、演练和处理方式，再保存。迁移测试使用合成配置；用户实际私人 JSON 无需上传。

## 翻译回退

保持原来的主模型配置仍可启用拒绝检测，或用本机按钮切换。默认同模型重试 1 次；不填备用模型时，仍拒绝或不可用就保留该字段原文。
备用设置现在可直接在翻译页编辑；对应 JSON 字段示例：

```json
{
  "llm_fallback_url": "https://api.deepseek.com/v1",
  "llm_fallback_key": "填写自己的 Key",
  "llm_fallback_model": "自己的可用模型 ID",
  "llm_fallback_read_timeout": 60,
  "llm_refusal_retries": 1
}
```

主模型的正常译文仍直接使用。实际发生拒绝时，日志会依次显示 `翻译被拒`、`重试第 1 次`、`换备用模型` 或 `保留原文`。
模型拒绝有随机性，正常调用不能保证重现；四条拒绝/回退路径已通过仓库模拟 LLM 测试，不需要改写提示词来强迫模型拒绝。
新生成的 NFO 中，简介应是正常译文或原文，不应是拒绝语。本功能不修复已有 NFO。

## 如何读日志

- `演练: ... | 黑名单:...`：已成功识别，只记录不移动。
- `Success 0, Failed 3`：统计的是正常视频刮削，不表示垃圾检测失败。
- `WinError 1314`：Windows 创建软链接缺少权限；可用管理员权限启动，或按自己的整理需求关闭软链接。它不会使垃圾判断失效。
- 没有整目录日志：仅凭日志不能确定剩余文件；若还有正常视频、NFO、图片、字幕、未知文件或链接，会保留目录。
