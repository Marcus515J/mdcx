# MDCx Windows 测试版：垃圾处理与翻译回退

这是独立预发布测试版，包含垃圾文件处理、翻译拒绝检测及刮削后纯垃圾目录整体移到 `_待删`。正式版和主分支未替换。

## 下载运行

在本 Release 下方的 **Assets** 下载名字以 `.exe` 结尾的文件；`Source code` 是源码，不是程序。
把程序放到独立测试目录后运行。已有配置仍可使用；测试时请选择新建的媒体测试目录，不要直接选整块盘。

## 启用测试设置

启动程序，在设置中保存一次，然后关闭程序。`MDCx.config` 中记录了当前 JSON 配置文件的位置，打开该文件修改以下现有键；不要重复添加同名键：

```json
{
  "garbage_enabled": true,
  "garbage_dry_run": true,
  "garbage_permanent_delete": false,
  "garbage_directory": "",
  "file_size": 100.0
}
```

这些是垃圾处理相关的键，合并到原配置中，不要用这个片段替换整个配置。
`garbage_directory` 空表示源文件盘符根下的 `_待删`。如要自定义，可填写例如 `"G:\\_待删"`。
测试期间关闭已有的自动清理、空目录删除及刮削后自动退出，方便对照演练前后文件。

## 第一轮：演练

在一个新的测试媒体目录里准备以下子目录：

1. `混合目录`：一份有正常番号的正常视频副本，例如 `FC2PPV-4057967.mp4`，另放 `社 區 最 新 情 報.mp4`。
2. `纯垃圾目录`：放 `社 區 最 新 情 報.mp4`、`推广.url`。推广链接文件按已有 `.url` 清理规则识别；未知文本/文档不会仅因很小而算垃圾。
3. `有正常文件的目录`：放一个垃圾视频，再放 `私人笔记.txt`；有 NFO、图片或字幕也会阻止整目录移动。

可用空文件或已有广告文件副本测试垃圾名称，但正常视频使用真实视频副本。避免复制已有 NFO，这次无需修改存量 NFO。
选择这个测试媒体目录开始刮削。

预期：垃圾文件不进入站点搜索；日志出现 `演练` 和 `演练目录`。纯垃圾目录的整体移动记录出现在整轮结束后。
垃圾处理的演练不会移动或删除文件。正常视频仍走正常刮削流程，所以它的文件改动不属于垃圾演练。

## 第二轮：真实处理

关闭程序，将 `garbage_dry_run` 改成 `false`，再启动并刮削。

预期：

- 混合目录中的垃圾视频被移入 `_待删`，正常视频不会被垃圾规则处理。
- 纯垃圾目录在本轮结束后整个移入 `_待删`，内部文件和子目录结构保留。
- 含正常视频、NFO、图片、字幕、未知文件或链接的目录不会整体移动。
- 同名文件/目录会加 `_1` 等序号，已有目标不会被覆盖。
- 再运行一轮，不会扫描 `_待删` 中的文件。
- 复制失败或处理期间出现新文件会记录日志、保留源文件；不会强制删除未知内容。

## 翻译回退

保持原来的主模型配置即可启用拒绝检测。默认同模型重试 1 次；不填备用模型时，仍拒绝就保留该字段原文。
如需备用模型，在原 `translate_config` 中合并：

```json
{
  "llm_fallback_url": "https://api.deepseek.com",
  "llm_fallback_key": "填写自己的 Key",
  "llm_fallback_model": "deepseek-flash",
  "llm_fallback_read_timeout": 60,
  "llm_refusal_retries": 1
}
```

主模型的正常译文仍直接使用。实际发生拒绝时，日志会依次显示 `翻译被拒`、`重试第 1 次`、`换备用模型` 或 `保留原文`。
模型拒绝有随机性，正常调用不能保证重现；四条拒绝/回退路径已通过仓库模拟 LLM 测试，不需要改写提示词来强迫模型拒绝。
新生成的 NFO 中，简介应是正常译文或原文，不应是拒绝语。本功能不修复已有 NFO。
