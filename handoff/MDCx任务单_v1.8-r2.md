任务单 v1.8 B1 明确要求：「每一条说明都要对照当前代码确认」「不要自己编造菜单名」。当前文本中有以下错误：

| 说明里的写法 | 实际情况 |

| 主温度默认 0.2，备用温度默认 1.0 | `models.py` 第 80 行主温度默认 0.9；备用温度默认等于主温度；`default_config.json` 里两者都是 0.9 |
| 「使用备用模型」开关 | 界面上没有这个开关。实际规则是：备用地址留空即停用（见 `llm_settings.py` 中的帮助文字） |

| 「使用演员数据库」 | 这几个字只出现在说明正文里，界面上没有。请按 `MDCx.ui` 里的实际控件文字来写 |
| 「保存配置」，以及「或勾选自动保存配置」 | 设置页底部的按钮叫「保存」（`pushButton_save_config`）。「自动保存配置」是否存在、叫什么，请核实；查不到就删掉这半句 |
| 「设置 → 分集」 | 设置页没有「分集」标签页。实际的标签页是：刮削目录、刮削模式、刮削网站、下载、命名、翻译、字幕、水印、NFO、演员、网络、高级。请找到分集设置实际所在的标签页 |

### R3. 删除「LLM」勾选框，翻译开关由用户控制（用户已定，不要改方向）

现状【已查证】：`save_config.py` 中写的是 `get_checkboxes(checkBox_llm) or [Translator.LLM]`，`TranslateConfig.normalize_translate_by` 会把空列表改成 `[LLM]`。用户取消勾选也不起作用，等于一个假开关。

用户的决定：引擎只剩大模型，**不需要选引擎**。删除 `checkBox_llm` 以及它所在的那一行（含左侧标签文字）。用户只需要能控制翻译「开 / 关」。

步骤（按顺序，每步结果写进汇报）：
1. **先查关闭翻译的入口**：`FieldConfig.translate`（按字段的翻译开关）在界面上是否可以设置。汇报中写明：所在标签页、分组名、控件的 objectName 和界面文字，并贴出 `MDCx.ui` 中对应的行号。
2. 删除 `checkBox_llm` 这一行：`.ui`、`scripts/pyuic.sh` 重新生成的文件、`save_config.py`、`load_config.py` 以及所有引用它的代码。
3. 关闭翻译的入口：
   - **步骤 1 查到了入口**：不新增控件。使用说明（`textBrowser_about`）里写一句：要关闭翻译，到「标签页 → 分组」里关闭对应字段的翻译开关。所用名称纳入 R1 第 2 条的机械核对。
   - **步骤 1 没查到入口**：在原来那一行的位置放一个勾选框，界面文字为「启用翻译」。勾选时 `translate_by = [LLM]`，不勾选时 `translate_by = []`，并且不翻译。同时在说明里写明这个开关。
4. 删除「空列表强制改为 `[LLM]`」的处理（`save_config.py` 的 `or [Translator.LLM]`，以及 `normalize_translate_by` 中把空列表改成 LLM 的分支）。`translate_by = []` 恢复原来的含义：不翻译。
   - 例外，保持 v1.8 的规则不变：旧配置的 `translate_by` 里**只有**被删除的引擎（如只有 google）时，载入后迁移为 `[LLM]`。
5. 补充测试（测试名写进汇报）：
   - 旧配置只含 google → 载入后为 `[LLM]`；
   - 旧配置为 `[]` → 载入后仍为 `[]`，保存后再载入仍为 `[]`；
   - `[]` 时翻译函数不被调用（用 mock 断言调用次数为 0）；
   - 若走步骤 3 第二种情况：勾选与不勾选两种状态各一条保存 / 载入往返测试。

机械核对（结果原样贴进汇报）：
- `git grep -n checkBox_llm` 在分支上输出为空；
- `git grep -n "or \[Translator.LLM\]"` 输出为空；
- 汇报写明步骤 3 走了哪种情况，依据是步骤 1 查到的行号。
