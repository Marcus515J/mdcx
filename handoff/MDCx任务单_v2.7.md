## B. 改（只改这两处）

从合并后的 master 切 `fix/anti-ban-step1`。

### B1 已知要过 bypass 的站，不再先直连

- 本次运行内，某 host 一旦拿到 Cloudflare 挑战页并由 bypass 成功取得页面，该 host 之后的请求**直接走 bypass**，不再先发直连。
- bypass 对该 host 失败时，行为与现在一致（不新增回退路径）。
- 运行结束即清空，不落盘，不新增配置项。
- 日志新增一行（每 host 每次运行只打一次）：`🛡️ [CF] <host> 已确认需要 bypass，本次运行后续请求直接走 bypass`。

### B2 断路器不因单部片超时停用整站

- 「单站单番号总等待超限」只放弃**这一部片**在该站的剩余请求，**不打开**该站本次运行的断路器。其他断路器触发条件（如「允许的请求尝试已耗尽」）不变。
- 计算单番号的 `site_total_timeout` 时，**不计**：等待站点冷却（排队）的时间、429 退避等待的时间。只计请求实际在途的时间。
- 汇报算出改后单部片在一个站上的最坏墙钟耗时（按并发 3、javlibrary 3 秒间隔、每片 3 个请求、`retry` 5、`timeout` 10、`cf_bypass_timeout` 90 推），写出算式。
